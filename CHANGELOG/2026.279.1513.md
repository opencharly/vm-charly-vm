# 2026.279.1513 — docs(vm): document the rootless-podman privileged-builder failure and the engine.rootful=sudo remedy

## Summary

The `vm` skill documented the **consequence** of `engine.rootful=sudo` (the rootful ↔
rootless storage split) but never the failure mode that makes the setting *required* —
so an operator on a host whose default engine is **rootless podman** saw an error naming
neither the cause nor the remedy:

```
mount: /target/sys: permission denied.
==> ERROR: failed to setup chroot /target
```

The cause is the user **namespace**, not sysfs itself: `--privileged` in a rootless
container has no `CAP_SYS_ADMIN` equivalent for arbitrary bind mounts, so pacstrap's
`mount --rbind` of the locked `/sys` is denied. `sudo podman` runs the builder in the
host namespace and bypasses it; the remedy is one setting:

```bash
charly settings set engine.rootful sudo
```

This adds a short section above the existing storage-split section, with the exact error
and the one-line fix.

Closes opencharly/vm-charly-vm#12.

## How tested

The failure and its remedy were measured live while bringing up a CachyOS bootstrap VM
(the `distro-cachyos#125` `check-dsh-cachyos-vm` bed):

```
$ sudo podman run --rm --privileged --user 0 --net host -v /dev:/dev alpine \
    sh -c 'mkdir -p /t/dev && mount --bind /dev /t/dev && echo BIND-OK'
BIND-OK
$ podman run --rm --privileged --user 0 --net host -v /dev:/dev alpine \
    sh -c 'mkdir -p /t/dev && mount --bind /dev /t/dev && echo BIND-OK'
mount: /t/dev: permission denied
```

With `engine.rootful=sudo` the CachyOS bootstrap VM built end to end (`vm-build` PASS).
